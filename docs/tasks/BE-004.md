# BE-004 — Setup sqlc + repository layer

Issue: [#4](https://github.com/jawir-team/jawir-sentinel-be/issues/4)  
Tanggal: 6 Oktober 2026  
Status: selesai secara lokal.

## Perubahan

| File | Perubahan |
|---|---|
| `sqlc.yaml` | Menghubungkan sqlc ke seluruh migration `*.up.sql`, query baseline, dan package generated `internal/db/sqlc`. |
| `db/queries/*.sql` | Query typed untuk master data, case, participant, policy, evidence, analysis, decision, execution, outbox, dan audit. Query lock menggunakan `FOR UPDATE`/`SKIP LOCKED`; tidak ada workflow transition atau authorization policy. |
| `Makefile` | Menambahkan `make sqlc` dengan `go run github.com/sqlc-dev/sqlc/cmd/sqlc@latest generate`. |
| `internal/db/sqlc/proof_test.go` | Read/write proof memakai generated query layer dan skip bila `TEST_DATABASE_URL`/`DATABASE_URL` tidak tersedia. |
| `internal/db/sqlc/*_sql.go`, `models.go`, `querier.go` | Output generated sqlc; jangan diedit manual. |

## Catatan

- Outbox query menjadi bagian baseline repository, termasuk pengambilan pending event dengan row lock.
- `vector` dipetakan ke `pgtype.Text` agar generated package tetap memakai dependency pgx yang sudah ada; query retrieval dapat mengonversi nilai vector di layer policy retrieval berikutnya.
- Migration BE-003 tidak diubah.
