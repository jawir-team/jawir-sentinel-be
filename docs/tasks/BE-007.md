# BE-007 — Firebase auth middleware

Issue: [#74](https://github.com/jawir-team/jawir-sentinel-be/issues/74)  
Tanggal: 6 Oktober 2026  
Status: selesai secara lokal; integrasi Firebase Admin menunggu kredensial runtime.

## Perubahan

| File | Perubahan |
|---|---|
| `internal/auth/context.go` | Menambahkan identity context berisi ID user, Firebase UID, nama, email, unit ID, dan system role. |
| `internal/auth/firebase.go` | Menambahkan boundary `TokenVerifier` dan verifier default yang gagal tertutup dengan `ErrVerifierNotConfigured`. |
| `internal/auth/middleware.go` | Memvalidasi bearer token, melakukan lookup `firebase_uid`, mewajibkan status `ACTIVE`, memvalidasi role `USER`/`ADMIN`, lalu memasang user internal ke context. Semua kegagalan autentikasi menghasilkan kontrak `UNAUTHORIZED` (401) yang sama. |
| `internal/auth/guard.go` | Menambahkan middleware reusable `RequireAdmin` dengan respons `FORBIDDEN` (403) untuk non-ADMIN. |
| `internal/db/sqlc/user.sql.go`, `querier.go` | Melengkapi output query user BE-004 yang belum ada pada generated package, termasuk `GetUserByFirebaseUID`. |
| `cmd/api/main.go` | Memasang auth pada scope `/api`; `/health` dan `/healthz` tetap dapat diakses tanpa autentikasi. |
| `internal/auth/*_test.go`, `cmd/api/main_test.go` | Menguji USER, ADMIN, token/header invalid, UID tidak terpetakan, user inactive, context, ADMIN guard, health endpoint, dan wiring protected route. |

## Aturan authorization

- `system_role` hanya menerima `USER` atau `ADMIN`.
- `ADMIN` adalah role system/global saja. Guard ini tidak menggantikan dan tidak melewati case role, segregation of duties, workflow state, maupun analysis guard.
- UID yang tidak terpetakan, user non-ACTIVE, data role invalid, serta kegagalan verifier/store menggunakan respons 401 yang sama agar detail identity internal tidak bocor.

## Gap kredensial Firebase

Environment ini tidak menyediakan kredensial Firebase dan repository belum membawa dependency `firebase-admin-go`. Karena itu `NewVerifier` saat ini menghasilkan verifier eksplisit yang selalu mengembalikan `ErrVerifierNotConfigured`; tidak ada token palsu atau jalur bypass. Endpoint health tetap hidup, tetapi request pada scope `/api` akan gagal 401 sampai implementation `TokenVerifier` berbasis Firebase Admin dan kredensial runtime dipasang.

Unit test tidak membutuhkan kredensial karena memakai fake `TokenVerifier` dan fake `UserStore` pada interface boundary.
