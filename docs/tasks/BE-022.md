# BE-022 — Vertex embedding integration

Tanggal: 6 Oktober 2026  
Status: implementasi dan pengujian lokal selesai; wiring kredensial runtime menunggu environment produksi.

## Implementasi

- `internal/embedding.VertexEmbedder` memanggil endpoint REST Vertex AI `gemini-embedding-001:predict` dengan task type `RETRIEVAL_DOCUMENT`, dimensi output 768, dan auto-truncation.
- `IndexPolicyVersion` memisahkan validasi lease, network call Vertex, dan finalisasi database menjadi tiga fase. Tidak ada transaksi database yang tetap terbuka selama network call.
- Hanya `index_attempt_id` yang masih aktif dapat mengganti chunk dan menerbitkan status `READY` atau mencatat `FAILED`. Attempt lama tidak memiliki otoritas untuk melakukan mutasi.
- Penggantian chunk dan transisi ke `READY` berada dalam satu transaksi sehingga kumpulan chunk parsial tidak dapat terlihat sebagai index siap pakai.
- Heading section dipotong hingga 150 Unicode rune sebelum disimpan ke kolom `VARCHAR(150)`. Embedding disimpan sebagai literal teks pgvector berbentuk `[v1,v2,...]`.

## Wiring kredensial produksi

Constructor membutuhkan access token non-kosong dan mengirimkannya sebagai Bearer token. Repository tidak menyimpan kredensial palsu, token default, atau jalur bypass. Wiring produksi harus menyediakan access token dari Secret Manager atau workload identity, termasuk lifecycle refresh token yang sesuai, lalu membangun `VertexEmbedder` pada composition root.

Test memakai HTTP server in-memory dan fake interface sehingga tidak membutuhkan kredensial maupun panggilan GCP nyata.
