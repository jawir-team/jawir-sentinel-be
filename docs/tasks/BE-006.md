## Keamanan logging

Handler melakukan redaksi otomatis berdasarkan nama key sensitif, termasuk prompt, evidence, policy content, credential, authorization, token, secret, password, dan API key. Nilai field tersebut tidak ditulis ke output log. Untuk menjaga log tetap aman dan mudah dikorelasikan, call site sebaiknya menggunakan allowlist metadata operasional berikut:

- ID dan status lifecycle, misalnya `request_id`, `outbox_event_id`, `analysis_id`, `case_id`, `rabbitmq_message_id`, `policy_version_id`, dan `index_attempt_id`.
- Metadata delivery/retry seperti `redelivered` dan `attempt`.
- Informasi error yang aman dan tidak memuat payload mentah.

Raw prompt, evidence, policy content, payload message, maupun credential tidak boleh diberikan sebagai field log. Redaksi menjadi lapisan perlindungan tambahan, bukan pengganti pemilihan field yang aman di call site.

## Catatan integrasi

- Incoming `X-Request-ID` dipertahankan agar request dapat dikorelasikan lintas service; jika header tidak ada, API menghasilkan UUID baru.
- `X-Request-ID` selalu tersedia pada response dan `request_id` tersedia melalui context untuk seluruh handler/middleware berikutnya.
- Repository saat ini belum memiliki runtime worker, consumer RabbitMQ, outbox dispatcher, maupun policy indexer. Helper scoped logger telah tersedia dan diuji untuk dipasang pada lifecycle tersebut ketika runtime terkait diimplementasikan; BE-006 tidak menambahkan worker baru.
