## Kontrak endpoint

`GET /api/v1/me` memerlukan Firebase bearer token yang valid dan user internal berstatus aktif. Response sukses menggunakan envelope standar:

```json
{
  "data": {
    "id": "00000000-0000-0000-0000-000000000001",
    "name": "Sentinel User",
    "email": "user@example.test",
    "system_role": "USER",
    "unit": {
      "id": "00000000-0000-0000-0000-000000000002",
      "code": "OPS",
      "name": "Operations"
    }
  }
}
```

Response hanya memuat global `system_role` dengan nilai `USER` atau `ADMIN`; Firebase UID, status user, case role, deskripsi unit, dan timestamp tidak diekspos.

## Keputusan routing dan unit

Router authentication yang sudah ada tetap di-mount pada `/api` untuk menjaga perilaku seluruh path terproteksi. Handler baru didaftarkan sebagai `/v1/me` di dalam router tersebut sehingga path publiknya tepat `/api/v1/me`. Tidak ada alias tanpa versi `/api/me`.

Schema saat ini mewajibkan `users.unit_id` dan middleware BE-007 menolak unit ID yang tidak valid, sehingga response normal selalu berisi object unit. Handler tetap menghasilkan `"unit": null` bila dipanggil dengan auth context tanpa unit ID sebagai fallback defensif; jalur ini tidak melakukan query database. Kegagalan lookup untuk unit ID yang valid diperlakukan sebagai `INTERNAL_ERROR`, bukan sebagai unit kosong, karena hal tersebut melanggar foreign-key invariant.
