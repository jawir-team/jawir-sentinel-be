## Catatan keputusan

- Satu initial migration dipakai agar urutan foreign key dan penambahan `cases.current_analysis_id` setelah `ai_analyses` tersedia tetap jelas.
- UUID tidak diberi default database karena baseline desain menetapkan UUID dibuat oleh aplikasi; extension `uuid-ossp` tetap diaktifkan sesuai spesifikasi dan dipakai untuk seed `case_types` MVP.
- `cases.owner_id = cases.created_by` dibackstop dengan `CHECK`; pembuatan participant Maker tetap menjadi invariant service karena relasinya lintas tabel.
- Lifecycle yang memerlukan waktu efektif saat ini tetap divalidasi oleh service; PostgreSQL menegakkan bentuk range dan status/index fields yang dapat divalidasi tanpa `now()`.
- Integration round-trip memakai database khusus yang disediakan melalui `TEST_DATABASE_URL`, karena rollback menghapus schema migration ini.

## Menjalankan

API menjalankan migration pending saat startup:

```bash
DATABASE_URL=postgres://sentinel:sentinel_local@127.0.0.1:5433/sentinel?sslmode=disable go run ./cmd/api
```

Untuk integration test, gunakan database PostgreSQL/pgvector khusus:

```bash
TEST_DATABASE_URL='postgres://sentinel:sentinel_local@127.0.0.1:5433/sentinel_test?sslmode=disable' go test ./internal/database
```

Tanpa `TEST_DATABASE_URL` maupun `DATABASE_URL`, integration test di-skip; unit checks tetap memvalidasi migration files.
